How Sumber works

Sumber is a search page for questions where the source matters. It asks up to 20 public libraries of human-written material at once, ranks what comes back with a formula you can read below, and prints nothing that a source did not write.

What it is for

Two things have made looking something up harder. Ordinary web results are crowded with pages written to rank and to sell: a study of 7,392 product-review queries found that higher-ranked pages were on average more optimised, more monetised with affiliate links, and showed signs of lower text quality (Bevendorff, Wiegmann, Potthast and Stein, ECIR 2024). And answer engines write confident text whose sources often do not check out: the Tow Center tested eight of them on 1,600 queries about news articles and they gave a wrong answer to more than 60 percent (Columbia Journalism Review, March 2025).

Sumber takes the opposite position on both. It only searches places that have no shop window to optimise for, and it never writes a sentence of its own. You get the source, the passage, the date, and the reason it is ranked where it is.

That makes it good for learning a topic, finding the paper, the accepted answer, the repository or the old discussion. It is the wrong tool for shopping, maps, local results and breaking news, and it says so on every results page.

How results are ranked

Every source returns its best six to eight items. Sumber pools them, removes duplicates, and gives each one a score. The whole formula is this:

base = 0.30 × text + 0.20 × evidence + 0.50 × source position + 0.08 if the title is exactly your query + up to 0.10 for items under five years old, only when the query says "latest", "new", "recent" or names this year or last score = base × lens weight × 0.85 ^ (earlier results from the same source)

Text, 0 to 1

BM25 over the title (counted 1.5 times), the excerpt, and tags or authors (counted 0.5 times), after stemming and dropping stop words. It is divided by the best BM25 in the pool and multiplied by 0.5 + 0.5 × coverage, where coverage is the share of your words that appear at all. If every word is in the title, 0.10 is added. With a quoted phrase, 0.15 is added when the phrase is found and the text score is multiplied by 0.6 when it is not. A result that contains none of your words is dropped.

Evidence, 0 to 1

Only numbers the source itself reports, on a logarithmic scale so that the hundredth vote matters less than the first.

Source position, 0 to 1

The sources search their full text. Sumber only sees the title and a short excerpt, so the order a source chose carries real information. First place is 1, and it falls evenly to the last item returned.

Lens weight and repeats

The lens multiplies the score by a value between 0.7 and 1.2 per source; in All it runs from 1.1 for Wikipedia to 0.85 for the Internet Archive, Europe PMC and the government sources. Each further result from the same source is multiplied by 0.85 again, so one source cannot fill the first screen.

Every result carries one line saying why it is where it is. Press the Why button under it to see these numbers for that result. Nothing else goes into the order: no payment, no click tracking, no profile of you. The code is one file, js/rank.js.

How these numbers were checked

The weights above were not picked by taste. A script asks 72 questions that each have one known right answer and records where it lands. On the half of the questions held back from tuning, the right answer is first for 76%, in the first three for 81% and in the first ten for 92%. The questions and answers were written by an AI assistant, 15 of the 72 saved answer sets are missing one source that had reached its limit, and it is a check on this formula, not a comparison with any other search engine. The questions, the saved answers and the script are in the repository: tools/eval.mjs.

How quotes are chosen

The block titled “In the sources’ own words” shows at most three sentences. Each is copied character for character from the excerpt of one of the top ten results. A sentence qualifies only if it is 40 to 320 characters long, is not a question, is not cut off, does not open with a word such as “It” or “This” that points back at an earlier sentence, and contains at least half of your query words. No sentence is shortened, joined to another, or reworded. If nothing qualifies, the block is not shown.

A quote is still only as right as its source. The number beside it jumps to the result it came from, so you can read the context before you rely on it.

The Before AI switch

ChatGPT was released on 30 November 2022. With the switch on, Sumber asks each source only for items dated on or before that day and drops anything without a date. It is a date filter, not a detector: it cannot prove a text was written by a person, and it hides good work published since.

Wikipedia articles keep changing, so in this mode the title links to the Internet Archive’s saved copy of the article from that date, the live page is offered as a second link, and Wikipedia text is left out of the quotes. You can set your own window with before: and after:.

Make it your default search

The address to give your browser is:

https://juw12.github.io/sumber/#q=%s

  • Chrome, Edge, Brave: Settings, Search engine, Manage search engines and site search, Add. Name it Sumber, give it a shortcut such as s, paste the address, save, then choose “Make default” from its menu.
  • Firefox: open Sumber, right-click the address bar and choose “Add Sumber”. Then pick it under Settings, Search, Default search engine.
  • Safari: Safari does not accept custom engines. Add Sumber to the home screen or the Dock instead (Share, Add to Home Screen).

The # matters. Everything after it stays inside your browser, so the server that delivers this page never receives your query. If your browser refuses an address with #, use ?q=%s. Sumber moves it behind the # at once, but the host can see that first request.

Because bangs work, making Sumber the default does not cut you off from anything: !g cheap flights still lands on Google.

Privacy

  • No Sumber server exists. The page is a set of static files on GitHub Pages. GitHub can log that your address loaded the page, as any web host can. It does not receive your query.
  • Your query goes to the sources you ask, from your own address, the same as if you had searched each of them yourself. They see the query and your IP address. Sumber sends no cookies and no referrer with it.
  • Nothing else can be contacted. The page carries a content security policy that lets it talk to those source hosts and nowhere else. There are no analytics, fonts, ads or scripts from third parties.
  • Stored in this browser only: your settings; your last eight searches, if you leave that on; up to 150 source answers; and a note of when a source asked the page to slow down. An answer counts as fresh for one hour (a day for Stack Exchange, GitHub, the web index and Wiktionary), so going back is instant. After that it is kept for up to 30 days and used only if the source fails, and then it is labelled “saved copy” with its age. “Clear saved searches and cache” in Settings deletes the searches and the cache, and your settings stay.
  • Links you follow open the source’s own site, and from then on its own privacy rules apply.
  • “Report this search” opens a GitHub issue form filled with your query and the list of sources. Nothing is sent unless you press submit there, and the issue is public.

What it cannot do

  • It is not a crawl of the whole web. The Mwmbl index gives it some ordinary web pages, but that index is small. If the answer is on a company site, a news site, a forum outside these sources, or a shop, Sumber will often not find it. Use a bang.
  • It is not a news wire. The only news source is Wikinews, which is written by volunteers and covers little. For today’s news use a bang.
  • The government sources cover two countries. GOV.UK and the United States Federal Register. Other countries’ records are not searched.
  • It matches words, not meaning. There is no language model, so a search for “car” does not find “automobile” unless the source’s own search does. Try the term the experts would use. When Wikipedia suggests a different spelling, Sumber passes it on as “Did you mean”, and that is all the help it gives.
  • It sees excerpts, not full pages. Ranking and quotes use the title and the few sentences each source returns.
  • It is built for languages with spaces between words. Wikipedia can be set to other languages, but the word matching is weak for Chinese, Japanese and Thai.
  • Sources set quotas per IP address. Stack Exchange allows about 300 requests a day and GitHub about 10 searches a minute without an account. On a shared office network they can run out. Sumber softens this in four ways: it reuses a saved copy of the same search, labelled as such; it asks GitLab when GitHub refuses; it shows how much quota is left once it runs low; and the code has an empty slot for a free Stack Apps key that raises the Stack Exchange quota. A new search on an exhausted source still gets nothing from it until the quota resets, and the rest still answer.
  • It depends on the sources staying open. If one changes or closes its interface, that source stops answering until the code is updated.
  • Popularity is not truth. Votes, stars and citations show that people paid attention, not that something is correct.

Who pays for it

Nobody has to. There is no server to rent and no search index to buy, so running Sumber costs nothing, and it is free with no account.

The code has room for two things, and both are empty unless they are filled in: a link where people can support the project, and one text line at the foot of the page that always begins with the word “Sponsor”. Neither can touch the results. The ranking code does not read them, and an automated test fails if it ever does.
